Cause: torch 2.8 enables TF32 for cuDNN convolutions by default, so on CUDA the 14x14
patch-embedding convolution was not float32. The node now sets `cudnn.allow_tf32 = False`
and `cuda.matmul.allow_tf32 = False`. The CPU output is bitwise identical before and after
the change (max abs diff 0.0). Turning TF32 off was the only change between the failing and
the passing GPU run.

clip_features still runs with the torch default (cuDNN TF32 on) for its patch convolution.
Its consistency passed at 0.999998, so it was not changed or re-run in this round.
